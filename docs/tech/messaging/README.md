# Слой обмена сообщениями

* Дата создания: 2025-04-08
* Дата обновления: 2026-03-31
* Версия: 4.2.13
* Статус: Реализовано

## Архитектурная модель

Слой обмена сообщениями отделяет обработчики предметной логики от транспорта.

Основные роли:

* сообщение — типизированный соглашение о взаимодействии; сообщения классифицируются как запрос, команда или событие;
* обработчик — компонент предметной логики, выполняющий обработку сообщения;
* вторичный адаптер — компонент, обеспечивающий отправку сообщения через выбранный транспорт;
* первичный адаптер — компонент, принимающий внешние сообщения;
* диспетчер сообщений — выбирает вторичный адаптер по типу сообщения и предоставляет единый интерфейс вызывающему коду;
* реестр сообщений и механизм сопоставления типов — связывает сериализованное имя сообщения с известным типом.

Поддерживаются отправка с результатом, отправка без результата, рассылка всем обработчикам и цепочка обработчиков с результатами.

## Принцип расширения

Для нового транспорта реализуются вторичный и первичный адаптеры, а также регистрируются соответствия типов сообщений. Обработчик предметной логики не должен зависеть от RabbitMQ, HTTP, SignalR или другой технологии.

## Жизненный цикл первичных адаптеров

Фоновые первичные адаптеры запускаются и останавливаются общим фоновым процессом.

## Открытый вопрос

Текущий контракт обработчиков частично отражает синхронность транспорта (`Consume`/`ConsumeWithResult`), хотя обработчик относится к слою предметной логики. Это архитектурный долг, зафиксированный исходным документом.
