# Модуль RabbitMQ

* Дата создания: 2025-04-04
* Дата обновления: 2026-03-31
* Версия: 4.2.13
* Статус: Реализовано

## Архитектурное решение

RabbitMQ — асинхронный транспортный адаптер общего слоя обмена сообщениями.

Для каждого типа сообщения используется стабильное имя маршрутизации, производное от полного имени типа. Основной поток использует устойчивые очереди кворума и ручное подтверждение обработки.

## Отправка и приём

Вторичный адаптер сериализует сообщение в JSON и публикует его в основную точку обмена. Первичный адаптер подписывается на разрешенные типы сообщений, десериализует входящее сообщение с помощью общего механизма сопоставления типов и передает его диспетчеру сообщений.

При успешной обработке первичный адаптер подтверждает сообщение. При исключении выполняется `nack` без `requeue`, после чего RabbitMQ направляет сообщение на обработку ошибок через DLX.

## Повторная обработка и очередь ошибок (DLQ)

Архитектура использует:

* основной exchange обмена с прямой маршрутизацией;
* exchange повторной обработки DLX;
* exchange окончательно отклонённых сообщений DLX;
* отдельные очереди quorum для повторной обработки и dead-letter сообщений.

Счетчик отказов берется из `x-death` и переносится в контекст сообщения.

## Служебное сообщение

Для служебных сценариев существует вариант, который сохраняет исходное содержимое сообщения, ключ маршрутизации, тип и заголовки, не пытаясь сразу материализовать прикладное сообщение.

## Открытые вопросы

Не зафиксирована окончательная стратегия владения RabbitMQ соединениями и каналами: одно общее соединение, постоянные или краткоживущие каналы, отдельные каналы обработчиков.
