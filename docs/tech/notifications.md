# Модуль оповещений

* Дата создания: 2023-01-01
* Дата обновления: 2024-08-16
* Версия документации: 1.1
* Статус: Легаси

## Архитектурное решение

Оповещение формируется в рамках бизнес-операции и хранится как отдельная запись с адресатом, содержимым, типом события, временем создания/прочтения и данными события.

Для прикладных событий предполагался механизм доменных событий. Создание оповещения должно происходить в одной транзакции с изменением бизнес-данных.

Доставка отделена от формирования: отдельный сервис периодически выбирает ожидающие оповещения и передает их транспортным обработчикам. Для веб-клиента в исходном решении выбран SignalR; мобильные уведомления на мобильные устройства вынесены за границы решения.

Клиент интерпретирует данные оповещения по типу события и после просмотра фиксирует время прочтения.

## Архитектурные компромиссы

* модель оповещения намеренно денормализована для упрощения чтения;
* синхронное формирование оповещения увеличивает длительность бизнес-операции;
* выбор SignalR был обусловлен уже существующим использованием технологии в проекте.
