# Модуль офлайн

* Дата создания: 2025-05-12
* Дата обновления: 2025-07-18
* Версия: 0.9
* Статус: Идет реализация

## Архитектурная модель

Офлайн-подсистема состоит из мобильного приложения и подготовки данных на бэкенде.

Клиент поддерживает три состояния: онлайн, полуофлайн и офлайн. В полуофлайне часть моделей уже обслуживается локальным хранилищем, а остальные продолжают работать через сервер. В полном офлайне разрешенные сценарии используют локальную базу данных.

## Подготовка данных

Сущности конфигурируются как:

* безусловные — подготавливаются заранее и периодически актуализируются;
* условные — загружаются непосредственно перед переходом в офлайн по прикладным ограничениям;
* неофлайновые — остаются только на сервере.

Для больших наборов сервер заранее формирует резервные копии в формате JSON, допускающие разделение по филиалу/другому разделителю и по частям. Клиент загружает резервную копию, затем догружает изменения и полномочия.

## Компоненты фронтенда

На высоком уровне фронтенд включает:

* описание набора офлайн-сущностей;
* хранение состояния режима и сведений, необходимых для восстановления пользовательской сессии;
* локальные адаптеры хранения;
* загрузчик и менеджер резервную копиюов;
* периодическую актуализацию;
* маршрутизацию запросов между бэкендом и локальным хранилищем;
* сервисы перехода офлайн/онлайн;
* интерфейс переключения и прогресса.

Прикладной проект переопределяет список сущностей и условия перехода/выгрузки.

## Компоненты бэкенда

Бэкенд определяет контракт описания резервной копии, запрос ее получения и фоновое формирование наборов данных. Резервная копия формируется по конфигурации сущностей и может ограничиваться филиалом и дополнительным разделителем.

## Важные ограничения

* редактирование справочников и операции, требующие внешней связи, должны ограничиваться прикладным кодом;
* в исходном проектировании хранение пароля/учетных данных в локальной модели помечено как сомнительное и требует отдельного проверки безопасности;
* фоновая работа на заблокированном/свернутом мобильном приложении обозначена как требующая дополнительного анализа.
