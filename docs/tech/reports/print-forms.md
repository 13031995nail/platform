# Модуль печатных форм

* Дата создания: 2024-06-28
* Дата обновления: 2024-12-11
* Версия: 2.0
* Статус: Реализовано

## Назначение

Модуль предоставляет приложениям платформы единый способ запрашивать печатные формы и отчёты независимо от конкретного средства их построения. Поддерживается выдача файлов в форматах PDF, DOCX, XLSX, HTML и CSV, массовая выгрузка и передача готовых файлов другим компонентам бэкенда (например, адаптеру отправки электронной почты).

## Архитектура

```text
Фронтенд (просмотр и загрузка)
          |
          v
Первичный адаптер бэкенда (приём запроса)
          |
          v
Базовый пакет модуля печатных форм
          |
          v
IReportAdapter (контракт вторичного адаптера)
          |
          v
Вторичный адаптер конкретного сервиса
          |
          v
Сервис построения печатных форм (например, Stimulsoft)
          |
          v
Готовый файл печатной формы / отчёта
```

- **Базовый пакет бэкенда** определяет контракт `IReportAdapter` и первичный адаптер для запросов фронтенда.
- **Пакет-реализация бэкенда** предоставляет вторичный адаптер, реализующий `IReportAdapter`. Он вызывает API конкретного сервиса построения печатных форм.
- **Пакет фронтенда** содержит интерфейсы предварительного просмотра и загрузки печатных форм актов, список отчётов и просмотр/загрузку отчёта.
- **Отдельный сервис построения форм** формирует документы по запросам через API.

## Реализация на Stimulsoft

Эталонная реализация. Сервис на Stimulsoft, работающий в Docker-контейнере. Он формирует отчёты с использованием таблицы `Report` и/или SQL-кода отчёта. Шаблоны разрабатываются в **Stimulsoft Designer**.

**Размещение шаблонов:** папка `Reports` в корне репозитория. При развёртывании она подключается к папке `Reports` внутри контейнера сервиса ПФ.

- [Исходники сервиса Stimulsoft](https://gitlab.timepath.ru/timepath/platform/tmobis/tmobis.core/-/tree/master/src/periphery/tech/reports/stimulsoft/tmobis.reports.stimulsoft.service?ref_type=heads)
- [Образ контейнера Stimulsoft](https://repository.flexberry.org/#browse/browse:docker:v2%2Ftimepath%2Ftmobis%2Fplatform%2Freports%2Fstimulsoft%2Ftags%2Flatest)

## Основные сценарии

1. **Просмотр или выгрузка из фронтенда:** интерфейс приложения обращается к первичному адаптеру; построение выполняется через вторичный адаптер и выделенный сервис; готовый файл возвращается вызывающей стороне.
2. **Получение файла внутри бэкенда:** компонент приложения запрашивает формирование файла и использует результат без обязательного участия фронтенда, например при отправке электронной почты.
3. **Массовая выгрузка:** платформа предусматривает запрос нескольких печатных форм; способ объединения и доставки результатов в исходном документе не определён.

## Точки расширения

Основная точка расширения — `IReportAdapter`. Различные реализации вторичного адаптера могут подключать разные сервисы построения форм без изменения общего контракта базового пакета. Требования к конкретным методам, формату запросов и обработке ошибок в исходном документе не описаны.
